# NN 测试工作台

当用户希望 AI 协助完成 NN 日常测试工作时使用本 Skill，例如：收集需求、提取验收标准、设计测试用例、准备测试数据、排查缺陷、总结进度，或在多个协作平台之间同步信息。

## 工作原则

- 将本仓库视为测试工作台的长期记忆，复用流程说明、平台适配说明和测试产物都沉淀在这里。
- 访问外部平台前，先读取 `platform-adapters/SKILL.md` 和 `platform-adapters/<platform>/SKILL.md` 中对应的平台适配说明。
- 安装任何 CLI 前，必须先读取 `references/cli-install-policy.md` 并按其中规则执行：先扫描本机，已安装则询问是否继续使用，未安装才统一安装到 `.agents` 目录下。
- 任何写操作前先完成只读确认。发送消息、更新单据、编辑文档等动作，必须确认用户已经提出明确请求。
- 平台内部标识只在工具调用中使用，不在最终回复中暴露用户 ID、文档 ID、访问令牌、会话 ID、游标等内部字段。禅道中用户可见的缺陷编号、任务编号可以作为公开引用。
- 信息冲突时，优先采用对应平台的事实来源：
  - 需求和设计依据：Confluence 或正式需求文档。
  - 任务和缺陷状态：禅道。
  - 实时讨论和临时决策：企业微信或飞书聊天。
  - 最终测试产物：本仓库，以及用户指定发布的平台。

## 常规流程

1. 判断用户请求类型：需求分析、测试设计、执行支持、缺陷分析、状态汇报，还是平台同步。
2. 当请求涉及多个平台，或事实来源不明确时，读取 `references/platform-routing.md`。
3. 当请求要求安装、升级或修复 CLI 时，读取 `references/cli-install-policy.md`。
4. 按需读取平台适配说明：
   - `platform-adapters/SKILL.md`
   - `platform-adapters/wecom/SKILL.md`
   - `platform-adapters/feishu/SKILL.md`
   - `platform-adapters/confluence/SKILL.md`
   - `platform-adapters/zentao/SKILL.md`
5. 根据平台适配说明中的本机路径、安装说明或 MCP 配置，调用正确的 CLI、MCP 或 API wrapper。
6. 对有复用价值的测试产物，保存到本仓库，例如测试计划、测试用例、缺陷分析、发版检查清单和复盘记录。

## 输出约定

- 测试计划应尽量包含范围、假设、风险、测试策略、环境、数据、准入标准、准出标准，以及已知的负责人/状态字段。
- 测试用例应尽量包含目标、前置条件、步骤、预期结果、优先级、测试数据，以及与需求或缺陷的追溯关系。
- 缺陷分析应区分实际表现、预期表现、影响范围、疑似模块、证据、复现步骤和后续负责人。
- 状态汇报应区分已完成、进行中、阻塞、风险、下一步动作和需要决策的问题。

## 平台登记

读取 `registry/platforms.yaml` 获取当前本机安装状态、已知命令路径和接入方式。
