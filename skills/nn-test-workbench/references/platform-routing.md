# 平台路由

当一个请求可能涉及多个平台时，使用本说明判断优先查询或写入哪个平台。

## 按意图选择主平台

| 意图                | 主平台        | 辅助平台                    |
| ----------------- | ---------- | ----------------------- |
| 查找近期讨论、决策或共享文件    | 企业微信或飞书    | Confluence、禅道           |
| 阅读或更新需求/设计文档      | Confluence | 企业微信、飞书                 |
| 跟踪缺陷、任务、需求或测试执行状态 | 禅道         | Confluence              |
| 安排会议或通知相关人        | 企业微信或飞书    | 可用的日历工具                 |
| 产出测试用例或测试计划       | 本仓库        | 需要发布时同步到 Confluence 或禅道 |
| 汇总某个版本或测试轮次       | 禅道和本仓库     | 企业微信/飞书提供讨论上下文          |

## 冲突处理

- 聊天消息与正式需求文档冲突时，说明冲突点，并询问是否需要更新正式文档。
- 禅道缺陷/任务状态与聊天讨论冲突时，以禅道当前状态为准，同时把聊天讨论作为上下文说明。
- 用户未指定平台时，先在本仓库内完成草稿或分析，再根据交付物类型推断发布平台；无法推断时再询问用户。

## 访问顺序

1. 先读取本地已有笔记和测试产物。
2. 查询事实来源平台。
3. 只有在需要近期讨论、人员协作或通知时，再查询聊天平台。
4. 只有在目标平台和写入内容明确后，才回写外部平台。
